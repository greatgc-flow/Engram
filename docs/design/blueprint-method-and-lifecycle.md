# Blueprint Method and Lifecycle Design

Compact synthesis of blueprint design rules, invariants, contracts, and decisions absorbed into Engram.
For repository background and historical findings, see [README.md](../../README.md), [CONTRIBUTING.md](../../CONTRIBUTING.md), [CONVENTION.md](../../CONVENTION.md), [release_gate.md](release_gate.md), and [audit-2026-10.md](../history/audit-2026-10.md).

## 1. Architecture and Design Invariants

| Rule / Invariant / Contract | Non-obvious Reasoning | Status |
|---|---|---|
| Primitive-first hierarchy: platform primitive > open standard > small OSS > framework > custom infra. Core safety invariants owned directly. | Avoids framework lock-in and dependency bloat; core data-safety invariants must never be outsourced to external libraries. | IMPLEMENTED (`_sys/core/backups.py`, `_sys/tests/unit/test_backups.py`) |
| Complexity budget: 5-question justification gate before adding daemons, tables, or services; single authority per mutable ledger. | Prevents feature sprawl and split-brain states; auxiliary component failure must never break core environment function. | IMPLEMENTED (`_sys/tests/unit/test_budget_single_authority.py`) |
| Prohibited defaults: zero speculative ('just-in-case') features, zero table/service sprawl, zero unverified AI self-reports. | Unexercised code creates phantom maintenance burden; unverified reports mask regressions. | IMPLEMENTED (`CONVENTION.md`, `_sys/tests/unit/test_boundary_imports.py`) |
| Boundary standardization: boundary type dictates protocol (native calls, SQLite API, env var redirection); standards express boundaries only. | Exposing internal domain structures to external protocol formats causes architectural ossification. | IMPLEMENTED (`_sys/core/launcher.py`, `_sys/tests/unit/test_launcher_paths.py`) |
| Declarative separation (No-code): mutable variations live in JSON catalogs; code retains only safety invariants and algorithms. | Allows runtime catalog adjustments without code deployment; isolates safety logic from data. | IMPLEMENTED (`_sys/dispatch.json`, `_sys/tests/unit/test_dispatch_wiring.py`) |
| SSOT view generation: human docs and CLI reference generated or verified verbatim against machine SSOT; no manual copying. | Manual copies inevitably drift from executable code and produce conflicting user-facing contracts. | IMPLEMENTED (`_sys/tests/unit/test_cli_help_contract.py`) |
| Commodity substitution: stdlib > DB transaction > CI platform > package manager > OSS before custom implementations. | Frameworks add ongoing maintenance tax; adopt only when inherent complexity exists and framework deletes net code. | IMPLEMENTED (`_sys/core/backups.py`, `tools/winget/build_package.py`) |
| Minimal global instructions: monolithic instruction files prohibited at root; procedures in skills/catalogs, only stable constraints global. | Bulky prompts dilute agent context attention and rot faster than modular procedures. | IMPLEMENTED (`_sys/tests/unit/test_doc_consistency.py`) |
| Deterministic skill materialization: single canonical Skill source deterministically projected to AI CLI harness target paths. | Prevents divergent skill copies across disparate CLI tools (Claude, Codex, Antigravity). | NOT IMPLEMENTED |
| AI domain & state decoupling: product core domain model strictly decoupled from AI agent runtime session/task models. | External agent frameworks evolve rapidly; the product environment bundler must remain agnostic. | IMPLEMENTED (`_sys/core/launcher.py`, `docs/engram-dotdir.md`) |
| Layered AI memory architecture: multi-tier memory (working, episodic, semantic, procedural) preserving source provenance. | Structured memory requires explicit provenance for auditability and context hydration. | SUPERSEDED (by personal config isolation under `<root>/.engram/`; see [engram-dotdir.md](../engram-dotdir.md)) |

## 2. Verification, Assurance and TDD Invariants

| Rule / Invariant / Contract | Non-obvious Reasoning | Status |
|---|---|---|
| Authority order: runtime execution > test > source code > current doc > ratified design > history > AI opinion. | Working empirical behavior always trumps stale documentation or speculative model commentary. | IMPLEMENTED (`CONVENTION.md`, `docs/history/audit-2026-10.md`) |
| Requirement trace & explicit disposition: no silent deletion; items classified as RETAIN, ABSORB, SUPERSEDE, DEFER, or RETIRE. | Silent drops hide regressions; explicit falsifiable triggers enable objective re-evaluation. | IMPLEMENTED (`docs/history/audit-2026-10.md`) |
| Recursive MECE completeness: 2D decomposition (13 lifecycle stages x 9 concerns); zero open exceptions (`COVERED`, `DEFERRED`, `OUT_OF_SCOPE`). | Unit tests in isolation miss combinatorial edge cases and unhandled state transitions. | IMPLEMENTED (`docs/history/audit-2026-10.md`, `_sys/tests/unit/test_doc_consistency.py`) |
| TDD vertical slice: slice from Req -> declared dimensions -> RED test -> minimum code -> gate; adequacy by dimension coverage. | High test counts with duplicate happy paths create false confidence while omitting edge dimensions. | IMPLEMENTED (`CONTRIBUTING.md`, `docs/history/audit-2026-10.md`) |
| AI verification rule: AI self-reporting is non-evidence; terminal/CI execution logs and clean-room proof required. | LLM hallucination and silent test skips produce deceptive green reports without real execution. | IMPLEMENTED (`docs/history/audit-2026-10.md`) |
| AI agent / skill repeatable evaluation: validate agent and skill changes with repeatable dataset/trace/eval benchmarks. | Subjective prompt assessment degrades silently without reproducible regression datasets. | NOT IMPLEMENTED |
| Machine-verifiable assurance closed loop: validate Req -> Test -> Gate -> Release -> Operate -> Learn via machine-readable SSOT. | Manual traceability matrices rot quickly; automated validation is required to prevent dangling references. | PARTIAL (`tools/release_gate/release_policy.json`, `tools/release_gate/check_required_tests.py`) |
| Implementation sequence: RED reproduction -> safety boundary -> candidate identity -> clean-room -> fault/upgrade -> promote. | Fixing containment and doc contracts first prevents amplifying data-safety defects during build work. | IMPLEMENTED (`docs/release_gate.md`, `docs/history/audit-2026-10.md`) |
| Defect 5-Whys depth: root-cause analysis must penetrate to missing test dimensions, contracts, or missing gates, not human error. | Blaming humans obscures architectural gaps; systemic failures stem from unverified dimensions. | IMPLEMENTED (`docs/history/audit-2026-10.md`) |

## 3. Release Lifecycle, Provenance and Operational Feedback

| Rule / Invariant / Contract | Non-obvious Reasoning | Status |
|---|---|---|
| Four completion stages: Done (tests pass) -> Released (gates pass) -> Operated (stabilized) -> Closed (disposition & watch). | Passing unit tests does not prove packaged binaries install cleanly or operate reliably. | IMPLEMENTED (`tools/release_gate/post_release_closure.py`, `_sys/tests/unit/test_post_release_closure.py`) |
| Pre-release immutable candidate: build once at G4; freeze hashes in `candidate.json`; downstream gates consume exact digest. | Rebuilding artifacts after testing invalidates test provenance and risks packaging discrepancies. | IMPLEMENTED (`_sys/checks/release_evidence.py`, `_sys/tests/unit/test_release_evidence.py`) |
| Gate evidence freshness: only fresh `status: PASS` tied to current candidate (`run_id`, `run_attempt`, hashes) satisfies gates. | Shared runner queue delays or cancelled runs must never be mistaken for release approval. | IMPLEMENTED (`_sys/checks/release_evidence.py`, `_sys/tests/unit/test_release_evidence.py`) |
| Candidate immutability on failure: never fix a candidate by rebuilding under same identity; issue new candidate run/attempt identity. | In-place asset replacement destroys audit trails and risks serving mismatched digests across mirrors. | IMPLEMENTED (`docs/release_gate.md`, `tools/release_gate/release_policy.json`) |
| Clean-room runner availability: runner unavailability or timeout triggers bounded HOLD (45-min deadline); never implicit pass. | Fail-closed execution prevents shipping untested bits when infrastructure fails. | IMPLEMENTED (`.github/scripts/wait_for_sandbox.js`, `_sys/tests/unit/test_wait_for_sandbox.py`) |
| Gate-driven tag promotion: G7 creates Git tag and release only AFTER G6 candidate gates pass, replacing tag-push triggers. | Tagging before validation marks unverified commits as releases in Git history before gates pass. | NOT IMPLEMENTED |
| Concurrency isolation: newer queued runs must not cancel running candidate verification; attempts strictly isolated. | Premature cancellation of active candidate gates causes false HOLDs on valid releases. | IMPLEMENTED (`.github/workflows/sandbox-gate.yml`, `.github/scripts/wait_for_sandbox.js`) |
| Post-release closure & upstream tracking: G8 verifies published digests against frozen hashes and monitors upstream WinGet merge. | Detects post-publication asset tampering, truncated uploads, or delayed package index propagation. | IMPLEMENTED (`.github/workflows/post-release-closure.yml`, `_sys/tests/unit/test_post_release_closure.py`) |
| Operational closed loop: triage failures to normalized evidence; defects close only with RED regression test + generic fix. | Anecdotal bug reports lead to ad-hoc patches; normalized evidence ensures durable root-cause fixes. | IMPLEMENTED (`docs/history/audit-2026-10.md`, `_sys/core/doctor.py`) |
| Post-publication incident disposition: digest mismatch -> revoke/replace; safety breach -> halt/patch; WinGet lag -> track open. | Compromised binaries demand immediate revocation; upstream packaging lag is non-blocking. | IMPLEMENTED (`tools/release_gate/post_release_closure.py`, `tools/release_gate/release_policy.json`) |
| CLI executable help as documentation SSOT: CLI help is SSOT; documentation drift on mutating flags is a safety-critical defect. | Out-of-sync guides trick users into believing dry-run commands mutated data or backups covered files. | IMPLEMENTED (`_sys/tests/unit/test_cli_help_contract.py`) |
