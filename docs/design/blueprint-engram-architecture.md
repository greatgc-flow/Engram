| A2: optional Windows Sandbox provider | Priority 1: disposable Windows isolation and clean-room proof. Detect newer `wsb` CLI capability (introduced with Windows 11 24H2), otherwise retain `.wsb`; automate start/list/exec/stop/share where supported. Since `wsb exec` exposes exit code without direct process stdout/stderr capture, guest result files on the dedicated evidence mount are canonical for both CLI and LogonCommand. Serialize jobs for the current one-instance-per-user limit, treating it as capability data rather than a permanent business constant. Guest build equals host build, so Sandbox cannot replace a cross-Windows-version matrix. | PARTIAL: `_sys/extensions/windows_sandbox/provider.py` implements the protocol with validated profile XML, raw CLI lifecycle probes, .wsb LogonCommand fallback, per-user leases, canonical guest evidence and verified teardown. Offline lifecycle tests pass; one opt-in live clean-room test is skipped by default and in CI. Raw list/stop remain necessary for verified fallback cleanup. Product command routing and delivery integration are not implemented. |
| A3: optional WSL2 provider | Priority 2: Linux compatibility/reproducibility, never security-equivalent to Sandbox because Windows filesystem/executable/network interop remains possible. Translate using `wslpath`/actual mount capabilities, never hardcode `/mnt/c`. Ephemeral profile: import -> exec -> collect -> optional export -> unregister, with explicit input/output.
