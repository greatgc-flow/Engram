# Signed release, core boundaries and paired fixture evidence

The fixture runner admits a canonical release manifest against the reviewed descriptor and a separate trust policy. It validates a detached Ed25519 signature with an exact local OpenSSL executable, verifies the archive digest and the complete program inventory, applies Windows-compatible path checks, and checks each uncompressed member before materialization. It checks the expected manifest digest, runtime lock, SBOM and license reference supplied by the fixture policy. Policy expiry and revocation block new staging and execution. Signing keys generated by tests live only in temporary roots. Real publisher identity, signed revocation distribution, trusted verifier/runtime installation and distribution rights have separate acceptance gates.

Signed generations live under the descriptor's relative slot. The current lifecycle journal publishes the exact manifest digest alongside fixture runtime state. The launch fence covers manifest and staged-byte validation through process creation. The selected interpreter is supplied by absolute path and hash. A subprocess deadline and output limit bound the paired adapter. The host validates protocol, scope-bound generation, response echo and receipt before accepting a result. Failure after launching an effectful adapter requires reconciliation. Re-running public effects is outside this fixture.

The core ZIP collector prunes all three reserved optional slot roots before traversal. A real archive test covered program and private sentinel bytes. The updater rejects optional-slot overlays before detached handoff, including names with Windows-equivalent case. Whole uninstall stops when package recovery state exists. These safeguards cover current tooling. Historical updater or executable downgrade and export-authorized whole uninstall need their own native proof.

## RED and GREEN

- Core archive RED reproduced 17 included files where the fixture expected the single core input and generated manifest. GREEN excluded all 15 package sentinels. The whole-uninstall RED reached the detached-helper path with its package state present. GREEN stops earlier and preserves that state.
- Signed admission RED initially had seven missing-module failures. GREEN exercised real Ed25519 verification, tampered bytes, revoked/expired trust and unsafe paths. The next RED required a signed generation bound to activation and successful execution after a root rename. RED for signed adapter invocation and deadline handling preceded GREEN for bound echoes, output size and time limits.
- The companion ContentFlow probe signs and stages a real, locally built dependency-free wheel in a disposable fixture. It checks a 25% native brief, health, checkpoint, duplicate reconciliation, policy-aware restore, interrupted signed update, rollback, and content execution after a same-volume Korean path rename. The host and app wire inputs are pinned to three frozen schema digests and the same descriptor bytes. This provides scoped evidence for CFX-01, 02, 04, 06, 07, 09 and 10. CFX-05 has its independent native media proof. Full native cross-volume runtime rebuild, uninstall receipts and all CFX release criteria remain gated.
- Windows draft CI supplies native core update, uninstall and signature verification receipts. Legacy updater and uninstaller suites use Windows registry, PowerShell and CMD, so their full Linux run is not a native oracle.
