# E2 optional package catalog

The catalog increment is based on the tested registry head of draft #145 (5202ca4), following #144 (e7b8e21). Its first consumer is an offline feasibility command operating on explicit synthetic data. Production catalog/trust enrollment and the public pack commands belong to later increments. Existing CLI verbs and help are compatibility oracles.

ContentFlow design 9a40fa4, design/engram-package-platform-v0.3, defines the descriptor v1.0 and tests. Its three frozen descriptors exercise reviewed slot overrides and the default packages/<id> convention. Generic code receives the reviewed slot mapping and validates descriptors before interpreting catalog metadata. The catalog conveys no install, runtime, account or launch authority.

The newer independent provider-admission branch f0ac2f7 was present at review. The WP1 registry writer calls env_ops.execute and owns the lock. Grouped runtime and app publication needs a single outer coordinator with prepare, journaled steps, recovery and launch fencing. Avoid a second writer. Keep the protected legacy binding, isolate mutable environment generations and retain unknown files. Release allowlisting, old updater compatibility, a verified out-of-target recovery inventory for uninstall, signed artifacts, offline trust freshness and a Windows standard-user exercise remain gates. WP0's two native interpreter probes and successful CI runs 46033092889/46039005106 are upstream observations only.

The ContentFlow branch carries the full cross-repository review, D0 canonicalization and historical traceability. Keep development independent from ongoing WP1–3. Fixture checks for the third package cover only the lifecycle stages actually exercised.

## Operator commands

Run from a development checkout. Point the catalog command at a disposable ordinary directory. PowerShell users can pass the three descriptor filenames explicitly.

```sh
python -B tools/feasibility/pack_catalog.py /path/to/synthetic-system _sys/tests/fixtures/optional-pack/*.descriptor.json
python -B tools/feasibility/pack_environments.py _sys/tests/fixtures/optional-pack/*.descriptor.json
python -B -m pytest -q _sys/tests/unit/test_optional_pack_catalog.py _sys/tests/unit/test_pack_environment_probe.py _sys/tests/unit/test_check_unreferenced_functions.py
```

The second command creates three temporary venvs with pip disabled. It loads each interpreter twice using isolated mode and an exact executable path. Each environment imports its own Python module, reports its base prefix, and checks its private workspace sentinel. The fixture roots are discarded after the run. Production package deployment, lockfile compatibility for real consumers, an installed-state reader and a public pack CLI require their separate gates.
