## Major side-track this session: OSS adoption strategy

User asked for unlimited-round dialectical research on strengthening
peerhub via open-source adoption (local LLMs, existing multi-agent
frameworks). 3-round process, documented in
`P:\peerhub\docs\design\OSS-ADOPTION-STRATEGY-2026-08-15.md`:

- Round 1: cx researched local-LLM runtimes (Ollama/vLLM/SGLang/etc.),
  ag researched multi-agent frameworks (LangGraph/OpenHands/CrewAI/etc.)
  + vendor ToS restrictions (all of Anthropic/OpenAI/Google now block
  routing consumer subscriptions through third-party harnesses -- API-key
  billing only).
- Genuine disagreement emerged: ag argued peerhub should pivot to being
  built ON TOP of LangGraph (discard the custom dispatch/authority
  kernel); cx argued the kernel should be preserved untouched, only a
  transport-neutral `HttpInvocation` addition for local models.
- Round 2 (cc, independent): verified every disputed claim against
  primary docs. LangGraph provides none of peerhub's guarantees
  (capability leases, fencing, concurrent-resume safety -- confirmed
  absent, not just undocumented). OpenHands genuinely has an "Agent
  Control Plane" matching peerhub's ambition almost exactly, but it's
  proprietary -- evidence FOR the open niche, not something to defer to.
- **Ratified verdict**: preserve the kernel as outer authority boundary;
  invert ag's stacking so LiteLLM (health/quota)/MCP (interop)/LangGraph
  or OpenHands SDK (optional per-attempt inner execution) sit BENEATH
  the kernel, not above it. Local LLM support = one new `HttpInvocation`
  execution class, not a 4th hand-written adapter.
- Follow-up compatibility audit (Section 9 of the same doc) confirmed the
  current design already accommodates this direction cleanly (transport
  layer, peer_kind, enforcement floor all already extensible) except one
  real gap: the adapter registry was a closed module-level dict --
  fixed with `register_adapter_factory()` (`81b6579`).

**This has NOT been implemented** -- it's a ratified direction doc only,
explicitly deferred as future work per the user's own framing ("추후
확장가능성으로 문서화 및 염두만").
